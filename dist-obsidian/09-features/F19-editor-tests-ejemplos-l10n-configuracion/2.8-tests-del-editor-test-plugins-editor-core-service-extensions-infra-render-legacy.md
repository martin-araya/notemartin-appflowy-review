# F19.2.8 — Tests del editor: `test/plugins/html/` (encoder y decoder HTML)

## 1. Resumen

Esta unidad cubre los **10 ficheros** de `editor/test/plugins/html/` que ejercitan el plugin HTML del editor `appflowy_editor`: el banco de fixtures `_samples.dart` (4 pares HTML↔Document), los 4 tests del encoder (`delta_encoder_test.dart` para `DeltaHTMLEncoder` y `document_html_encoder_test.dart` + 5 tests por parser para los parsers por tipo de bloque), el decoder (`document_html_decoder_test.dart` sobre `DocumentHTMLDecoder`), y el harness de la fachada pública `htmlToDocument` (`html_document_test.dart` con 12 casos que cubren formato inline, listas anidadas, tablas, pegados de Notion/Google Docs y `<meta charset>`). Son **2 469 LOC**, **45 casos `test()`** y **9 `group()`** `[VERIFICADO]` (medido con `rg -c '^\s*test\('` y `rg -c '^\s*group\('` sobre los 10 ficheros). Estos tests son la única especificación ejecutable de los formatos de exportación e importación HTML del editor y, por extensión, son la fuente de evidencia para la **matriz de fidelidad B4.13** del motor de export/import (`OUT/10-motor-export-import/`, pendiente) sobre lo que se preserva y se pierde en el round-trip documento↔HTML↔documento — el decoder devuelve una lista de `Node` con sus `delta` reconstruidos a partir de CSS `inline`, mientras que el encoder aplana cada `Node` por tipo invocando un `HTMLNodeParser`.

### 3.2 `DeltaHTMLEncoder` — el contrato inline

`DeltaHTMLEncoder` (`editor:lib/src/plugins/html/encoder/delta_html_encoder.dart:11`) opera sobre `TextInsert` de `Delta` y distingue tres ramas: sin atributos devuelve `dom.Text` (`:24–26`); con un único atributo intenta usar la etiqueta directa (`editor:lib/src/plugins/html/encoder/delta_html_encoder.dart:36–67`) con la tabla `keyToTag` (`:56–63`), pero **redirige a multi-atributo si hay `href`, `backgroundColor` o `color`** (`:46–53`); con varios atributos genera un `<span style="…">` con CSS concatenado (`:69–85`). El caso **`href` con otros atributos** produce un `<a><u|strong|em|...></a>` anidado (`editor:lib/src/plugins/html/encoder/delta_html_encoder.dart:87–125`), exactamente como sale en `editor:test/plugins/html/delta_encoder_test.dart:212–306` ("composition", que verifica la jerarquía `<a><u><i><strong>AppFlowy</strong></i></u></a>` leyendo `.localName` por nivel).

## 4. Eventos FFI

Ninguno. Esta unidad es 100 % Dart puro del repo `appflowy-editor`; ninguno de los 10 ficheros importa `package:appflowy_backend` ni toca la FFI. El plugin HTML del editor se ejecuta del lado de Dart tanto a la hora de exportar (`documentToHTML`, `editor:lib/src/plugins/html/html_document.dart:18`) como a la hora de importar (`htmlToDocument`, `editor:lib/src/plugins/html/html_document.dart:13`). ```

*Diagrama: los estados del round-trip.* Lectura: cuando el encoder serializa un párrafo con `delta` vacío, emite `<br>` (`editor:lib/src/plugins/html/encoder/parser/text_node_parser.dart:33–34`, verificado en `editor:test/plugins/html/encoder/parser/text_node_parser_test.dart:49–60`). | `paragraph` con `bold`+`italic`+`underline`+`strikethrough` inline | el HTML emite `<span style="…">` con `font-weight`, `text-decoration`, `font-style` (varios atributos) — el decoder reaplica `font-weight >=500 → bold`, `text-decoration: line-through → strikethrough`, `font-style:italic → italic` (`editor:lib/src/plugins/html/html_document_decoder.dart:421–482`) y reconstruye los 4 atributos | `editor:test/plugins/html/encoder/parser/text_node_parser_test.dart:181–201` verifica la concatenación correcta; la pérdida potencial es **el orden** de los atributos en el delta reconstruido, que el sample 5 (`:88–123`) no comprueba explícitamente `[INFERIDO: probable]` |
| `paragraph` con `bg_color`+`font_color` | el HTML emite `rgba(r, g, b, a)` con `a` decimal (`:127–148`); el decoder re-convierte de CSS a hex con `tryToColor()?.toHex()` (`:453`) | `editor:test/plugins/html/encoder/parser/text_node_parser_test.dart:202–226` muestra que `0x6000bcf0` (alpha `0x60 = 96`) se emite como `rgba(0, 188, 240, 96)`, no como `0x60` textual — esto significa que al re-decodificar el alpha se **reconstruye a partir de 96**, no del original `0x60`, lo que sí es matemáticamente reversible pero **firma de formato distinta** |
| `image` con `align: 'center'` | el HTML emite `<img src="…" align="center">` (`editor:lib/src/plugins/html/encoder/parser/image_node_parser.dart:25–41`) — pero el decoder no lee `align` (`editor:lib/src/plugins/html/html_document_decoder.dart:364–373`); muestra un `ImageNode(url: src)` simple | pérdida verificada: `align` no aparece en `editor:test/plugins/html/decoder/_samples.dart:428` que sí lo tenía en la entrada (`editor:test/plugins/html/decoder/_samples.dart:380` con `align="center"`) |
| Tabla 2×2 (`editor:test/plugins/html/decoder/_samples.dart:275`) | `<table>` ↔ `TableNode` con `colsLen: 2`, `rowsLen: 2`, `colDefaultWidth: 160`, `rowDefaultHeight: 40`, `colMinimumWidth: 40` | el `height`/`width` por celda, si fueron configurados, se pierden en la salida (el encoder no los usa: `editor:lib/src/plugins/html/encoder/parser/table_node_parser.dart:39–55`) |
| `<input type="checkbox" checked="">` (todo_list) | encoder emite `checked=""` (`editor:lib/src/plugins/html/encoder/parser/todo_list_node_parser.dart:30–33`); decoder acepta `input` en `specialElements` (`editor:lib/src/plugins/html/html_document_decoder.dart:568`) pero **no** implementa rama en `_parseSpecialElements` (`:87–127`), así que cae en el `default: _parseParagraphElement` | el atributo `checked` se **pierde** — el decoder no sabe que `<input type="checkbox">` es un to-do de AppFlowy. El fixture `_samples.dart` no incluye ningún to-do, por lo que esta pérdida no tiene caso de prueba directo `[VERIFICADO: por código y por ausencia de test]` |
| `<a href="…">…</a>` (anchor) | encoder emite `<a href="…"><strong|i|u|…>…</strong|i|u|…></a>` (`editor:lib/src/plugins/html/encoder/delta_html_encoder.dart:87–125`); decoder extrae `href` y lo aplica como atributo `href` del delta (`editor:lib/src/plugins/html/html_document_decoder.dart:285–290`) | atributos `rel="noopener noreferrer"`, `target="_blank"` se ignoran (decoder sólo lee `href`) |
| `<code>` vs `<span style="…">…</span>` para "inline code" | el decoder distingue ambos: `code` produce `{code: true}` (`editor:lib/src/plugins/html/html_document_decoder.dart:276–278`); `span` con CSS sólo produce `bg_color`/`font_color` (`:451–476`) | dos estilos visualmente idénticos producen deltas materialmente diferentes: `editor:test/plugins/html/html_document_test.dart:88–123` (sample 5) demuestra la pérdida del atributo `code: true` cuando se usa `<span>`. Eso significa que **redondear Notion → AppFlowy → Notion no es idempotente** si la fuente es `<span>` |
| `<b style="font-weight:normal;">` (Google Docs) | tratado como transparente (`editor:lib/src/plugins/html/html_document_decoder.dart:52–55`) | los atributos `id`, `data-*` del `<b>` se pierden |
| `<span style="text-decoration:underline line-through">` | decoder lee `text-decoration`, lo separa por espacios y asigna `underline` y `strikethrough` (`editor:lib/src/plugins/html/html_document_decoder.dart:434–449`) | no hay pérdida |

El siguiente diagrama resume el round-trip documento → HTML → documento y qué decisiones de pérdida/preservación aplica cada paso:

```mermaid
flowchart LR
  subgraph Editor["AppFlowy Document"]
    D1["Node type=paragraph<br/>delta=[bold+italic+underline+strikethrough]<br/>bg_color=0x6000bcf0"]
  end

    E2["<span style='font-weight:bold;text-decoration:underline line-through;...'>"]

  end
  subgraph HTML["HTML intermedio"]
    H1["<p><span style='...'>...</span></p>"]
  end
  subgraph Decoder["DocumentHTMLDecoder"]
    D2["_parserFormattingElementAttributes<br/>reconoce bold, italic, underline, strikethrough,<br/>bg_color, font_color, font-style, href"]
    D3["decodifica CSS -> atributos del delta<br/>_getDeltaAttributesFromHTMLAttributes"]

  end

  D4 -. "orden de atributos puede diferir" .-> D1
```

*Diagrama: camino feliz y puntos de pérdida del round-trip.* Lectura: `DeltaHTMLEncoder` agrupa atributos inline en un `<span>` cuando hay más de uno (rama "multi-attribute" en `editor:lib/src/plugins/html/encoder/delta_html_encoder.dart:69–85`), y para `bg_color`/`font_color` materializa `rgba(r, g, b, a)` con `a` decimal (`editor:lib/src/plugins/html/encoder/delta_html_encoder.dart:127–148`). El decoder **sólo** lee del CSS las 6 claves del whitelist (`editor:lib/src/plugins/html/html_document_decoder.dart:421–483`), por lo que cualquier otra propiedad (clase, id, font-family, font-size, letter-spacing, white-space, …) se descarta en `D2 → D3`. La flecha punteada `D4 → D1` marca el `[INFERIDO]`: el orden de atributos en el delta reconstruido depende del orden de lectura del CSS, que ningún test compara con el original.
